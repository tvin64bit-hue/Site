# Re Forel — лендинг

Вёрстка по `SPEC.md`. Чистый HTML/CSS/JS, без фреймворков, без сборщиков,
без внешних JS-библиотек. Node нужен только для офлайн-генерации картинок —
сам сайт от него не зависит.

Открывается как `index.html` напрямую с диска. Единственное, что для этого
потребует сети, — шрифты Google Fonts и iframe карты; всё остальное локально.

```
index.html
favicon.svg
css/styles.css              единственный стиль: токены → reset → сетка →
                            типографика → компоненты → секции 1–7 → движение
js/parallax.js              движок параллакса
js/ui.js                    шапка, мобильное меню, табы, reveal-эффекты
images/                     исходники (не изменялись)
images/derived/             сгенерированные варианты + manifest.json
images/placeholders/        сгенерированные заливки
tools/build-images.mjs      генератор derived/
tools/build-placeholders.mjs генератор placeholders/
```

## Пересборка ассетов

```bash
npm install          # ставит sharp (только для сборки)
npm run build:assets # images/derived/ + images/placeholders/
```

`images/derived/` закоммичен намеренно: без него страница после клонирования
не работает, а сборщика в проекте нет. 145 файлов, ~12 МБ. Генераторы
детерминированы — повторный запуск даёт тот же результат байт в байт.

## Параллакс

Слой со speed factor `s` движется со скоростью `s ×` скорость скролла.
Относительно нормального потока (скорость 1×) смещение равно
`(s − 1) × пройденный путь`. Путь отсчитывается от момента, когда секция
оказалась по центру экрана:

```
centerDelta = rect.top + rect.height / 2 − viewportH / 2
shift       = (s − 1) × clamp(centerDelta, −A, +A)
```

Проверка: `s = 0.35`, проскроллили 500px → `centerDelta = −500` →
`shift = (−0.65)(−500) = +325px`, то есть по экрану слой поднялся на
`500 − 325 = 175 = 0.35 × 500`. При `s = 1` сдвиг тождественно ноль —
«статичен относительно скролла», как и требует ТЗ.

**Амплитуда `A`** — единственное ограничение поверх формулы. Без него слой
с `s = 0.3` за проход секции по экрану уехал бы на ~700px и порвал бы вёрстку.
`A` едина для всех слоёв сцены, поэтому соотношения между ними остаются ровно
те, что в ТЗ: относительное движение двух слоёв — это в точности
`(s₁ − 1) : (s₂ − 1)`.

* `A = 0.5 × viewportH` для секций (`--parallax-amp`)
* `A = 1.0 × viewportH` для hero (`data-amp="1"`, отсчёт от верха страницы)
* `A = 0.4 × viewportH` для тарелок меню — им нужен «всплыв», а не полёт

**Брейкпоинты.** Множитель `k` читается движком из CSS-переменной
`--parallax-k`, чтобы границы брейкпоинтов жили только в стилях:
`k = 1` на desktop/laptop, `0.5` на tablet («ослабляется вдвое»), `0` на mobile
и при `prefers-reduced-motion: reduce`. Эффективная скорость —
`s_eff = 1 + (s − 1) × k`. Для hero ТЗ называет планшетные значения явно
(0.6 / 0.9 / 1.1) — они лежат в `data-speed-tablet` и имеют приоритет над формулой.

**Разметка слоя:**

```html
<div class="p-frame">                       <!-- рамка: держит сетку, клипует -->
  <div class="p-layer" data-parallax
       data-speed="0.6" data-anchor="frame"> <!-- слой: его и двигаем -->
```

`data-speed-tablet`, `data-amp`, `data-offset` (разброс по Y),
`data-mode="hero"`, `data-anchor="frame|parent"` — необязательные.

**Медленные слои (`s < 1`)** лежат внутри `.p-frame` с `overflow: hidden`
и переразмерены на `--overscan = |s − 1| × A` сверху и снизу — иначе на краях
появлялись бы пустоты. `--overscan` выставляет движок.

## Производительность

Всё из раздела примечаний ТЗ:

* **Только `transform` и `opacity`.** Ни `top`, ни `margin` в анимации нет,
  layout не пересчитывается.
* **`will-change: transform` ставится по входу слоя в кадр и снимается
  на выходе.** Проверено: внизу страницы промотированы 2 слоя из 26.
* **Один слушатель скролла** (`{ passive: true }`), **один rAF**,
  **один IntersectionObserver** на все 26 слоёв. Кадр разделён на фазы:
  сначала читаются все `getBoundingClientRect`, потом пишутся все `transform` —
  иначе каждая запись вызывала бы forced reflow.
* **`prefers-reduced-motion: reduce`** обнуляет сдвиги и в CSS, и в JS;
  остаётся только fade-in. Настройка отслеживается на лету, без перезагрузки.
* **`<picture>` + `srcset`** с AVIF / WebP / JPEG на всех фотографиях,
  ширины 368–2560 по реальной роли кадра, `sizes` посчитаны под сетку.
* **`loading="lazy"` на всём, кроме первого экрана**: приоритетно грузятся
  hero и первые две карточки галереи (14 из 17 изображений ленивые).
  Hero дополнительно получает `<link rel="preload">` и `fetchpriority="high"`.
* **`width`/`height` на каждом изображении** — CLS нулевой.

`content-visibility: auto` намеренно не применён: он пропускает рендер
за пределами экрана, из-за чего `getBoundingClientRect` параллакс-слоёв
возвращал бы размер-заглушку и слои дёргались бы при входе в кадр.

## Доступность

Проверено в Chromium: skip-link, видимый фокус на всех интерактивных
элементах, `lang="ru"`, осмысленные `alt` (декоративные слои — `aria-hidden`),
иерархия заголовков без пропусков уровней.

Табы «Пространства» — полный паттерн `tablist`: `aria-selected`,
roving `tabindex`, стрелки, `Home`/`End`, `role="tabpanel"`.
Мобильное меню — `aria-expanded` + закрытие по `Escape`.

Контраст: все текстовые пары ≥ 4.5:1 (минимум 5.53:1 — копирайт в футере).

Без JavaScript страница читается полностью: класс `.js` ставится синхронно
в `<head>`, поэтому reveal-блоки не залипают в `opacity: 0`.

## Временные заливки

Фотографий под два блока в наборе нет вообще. Вместо повтора чужих кадров —
сгенерированные заливки в брендовой палитре, каждая помечена бейджем
«фото готовится», чтобы заглушку нельзя было принять за фотографию.

| Что | Файл | Почему |
|---|---|---|
| 4 блюда для §5 | `dish-01…04.svg` | фотографий еды нет ни одной |
| Терраса для §4 | `terrace.svg` | нет ни одного уличного кадра |
| Частицы света в hero | `particles.svg` | декоративный слой, фотографией и не должен быть |
| Текстура фона §2 | `grain.svg` | то же |

Тарелки нарисованы на прозрачном фоне — тогда `filter: drop-shadow()` из ТЗ
даёт настоящую «парящую тарелку». Композиция террасы собрана в полосе
`y ∈ [200, 700]`: слой параллакса переразмерен на overscan, и в покое видна
только центральная часть кадра.

Все двенадцать реальных фотографий использованы по одному разу, без повторов.

## Отступления от ТЗ

1. **Параллакс карточек галереи применяется к изображению внутри рамки,
   а не к самой карточке.** ТЗ говорит «применяет translateY индивидуально
   к каждой карточке», но при `s = 0.6` ход составляет ~180px, и соседние
   карточки masonry наезжали бы друг на друга. `data-speed` остался на карточке,
   рамка держит сетку, движется фото внутри. Визуально эффект тот же.
2. **Амплитуда `A`** ограничивает общий ход (см. выше). Соотношения
   между слоями сохранены точно.
3. **Кнопки «Забронировать» нет нигде** — по отдельной просьбе. В карточке
   контактов её место занимает кнопка `tel:` во всю ширину, раскладка ТЗ цела.
4. **Шапка добавлена** сверх ТЗ (в ТЗ её нет) — по отдельной договорённости.
5. **Верхний градиент в hero** (`.hero__scrim--top`, 28% высоты) добавлен
   сверх ТЗ: без него белый логотип нечитаем на светлых участках кадра.
   Нижний градиент — ровно из ТЗ: 50% высоты, те же значения rgba.
6. **`max-width: 1320px` прочитан как ширина контента**, поля 80/40/20
   лежат снаружи: на широком экране контент ровно 1320px, до края — `--pad`.
7. **Hero: «left-align на уровне 60% от нижнего края»** прочитан как
   «текстовый блок живёт в нижних 40% экрана», ширина ограничена 640px.
8. **Карта на mobile**: ТЗ называет и `aspect-ratio: 16/9`, и высоту 320px.
   Взято и то и другое — `aspect-ratio` управляет, `min-height: 320px` служит полом.
9. **Laptop использует desktop-типографику** — в таблице шкалы ТЗ колонки
   Laptop нет. Отступы при этом уменьшены на 20%, как требует таблица брейкпоинтов.
