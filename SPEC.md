Детальное ТЗ на вёрстку лендинга Re Forel
Глобальные параметры (общие для всех блоков)

Брейкпоинты:

Название	Ширина	Комментарий
Desktop	≥1440px	основной дизайн
Laptop	1024–1439px	сетка сужается, отступы уменьшаются на ~20%
Tablet	768–1023px	1–2 колонки вместо 2–3, параллакс ослабляется вдвое
Mobile	375–767px	1 колонка, параллакс-эффекты отключены или сведены к минимуму (для производительности и укачивания)

Сетка: 12-колоночная, контейнер max-width 1320px, поля контейнера — 80px (desktop), 40px (tablet), 20px (mobile). Gutter между колонками — 24px.

Типографическая шкала (базовая, желаемая — на основе Cormorant Garamond / Jost):

Стиль	Desktop	Tablet	Mobile
H1 (hero)	72px / 1.1	48px / 1.15	34px / 1.2
H2 (заголовок секции)	48px / 1.2	36px / 1.2	28px / 1.25
H3 (подзаголовок)	28px / 1.3	24px / 1.3	20px / 1.35
Body	18px / 1.6	17px / 1.6	16px / 1.6
Small/caption	14px / 1.5	14px / 1.5	13px / 1.5

Вертикальные отступы секций: 160px сверху/снизу на desktop, 100px на tablet, 64px на mobile — кроме hero (на всю высоту экрана) и футера (compact, 64/48/32px).

Общий принцип параллакса (технически): реализуется через CSS transform: translateY(), значение которого пересчитывается по позиции скролла (через IntersectionObserver + requestAnimationFrame, без сторонних библиотек, либо через библиотеку типа Lenis/GSAP ScrollTrigger, если проект на JS-фреймворке). Каждому слою задаётся коэффициент скорости (speed factor) относительно скролла — значения ниже описаны по блокам. На mobile — либо отключаем через prefers-reduced-motion/media query, либо оставляем только самый лёгкий слой (0.9–1x), чтобы не создавать лишнюю нагрузку на GPU и не провоцировать укачивание.

1. Hero

Высота: 100vh (min-height: 640px на случай маленьких экранов по высоте, с fallback на 100svh для мобильных браузеров с динамической панелью адреса).

Сетка: контент выровнен по центру или left-aligned нижняя треть экрана (зависит от финального дизайна) — рекомендую left-align на уровне 60% от нижнего края, ширина текстового блока — до 640px (не на всю ширину, для премиального ощущения воздуха).

Отступы: padding контейнера как у глобального контейнера, дополнительный нижний отступ до CTA-кнопок — 48px.

Изображения: фон — 2560×1440px (desktop), с адаптивными версиями через srcset/<picture> для 1440/1024/768/480px по ширине; формат WebP/AVIF с фолбэком JPEG. Затемняющий градиент снизу: linear-gradient(to top, rgba(18,48,46,0.7), rgba(18,48,46,0)), высота градиента — 50% от высоты блока.

Кнопки CTA: размер 56px высотой на desktop / 48px на mobile, минимум 2 кнопки в ряд с gap 16px, на mobile — друг под другом на всю ширину контейнера.

Параллакс:

Фоновое изображение/видео: speed factor 0.35 (двигается медленнее скролла)
Текстовый блок (H1 + подзаголовок): speed factor 0.85
Декоративный слой (частицы света): speed factor 1.25, opacity 0.4–0.6
На tablet — коэффициенты приближаются к 0.6/0.9/1.1 (эффект слабее), на mobile — параллакс отключён, статичный фон с лёгким fade-in при загрузке.
2. О ресторане

Сетка: 2 колонки на desktop (текст — 7 колонок из 12, фото-деталь — 4 колонки, с отступом-разрывом в 1 колонку), на tablet — текст 8/12 + фото 4/12 либо фото уходит под текст, на mobile — 1 колонка, фото под текстом.

Типографика: H2 сверху блока, ниже — цитата увеличенным начертанием (32px desktop / 22px mobile, курсив или акцентный вес), затем body-текст обычным начертанием.

Отступы: между H2 и цитатой — 32px, между цитатой и текстом — 24px, между абзацами — 16px.

Изображения: фото-деталь — соотношение сторон 3:4 (портретное), ширина ~420px на desktop, объект-позиционирование object-fit: cover.

Параллакс:

Текстовая текстура фона секции: speed factor 0.5
Основной текстовый блок: 1.0 (статичен относительно скролла, без сдвига)
Фото-деталь сбоку: speed factor 1.2, дополнительно — плавное появление через opacity/translateY(40px→0) при входе в viewport (через IntersectionObserver, threshold 0.3)
3. Атмосфера и интерьер (галерея)

Сетка: асимметричный masonry-грид, 12 колонок, карточки занимают 4/5/6/7 колонок в разных комбинациях (не менее 3 разных размеров карточек для избежания монотонности). Gap между карточками — 16px (desktop), 12px (mobile). На tablet — грид упрощается до 2 колонок равной ширины, на mobile — 1 колонка, вертикальный список.

Изображения: соотношение сторон варьируется по карточкам (4:3, 3:4, 1:1, 16:9), реальные размеры файлов — от 800×600 до 1600×1200px в зависимости от размера карточки, все — с loading="lazy" кроме первых 2 карточек (above the fold).

Отступы: между заголовком секции и началом грида — 64px.

Параллакс:

Крупные «якорные» карточки (занимающие 6-7 колонок): speed factor 0.6
Средние карточки (4-5 колонок): speed factor 0.9
Мелкие карточки: speed factor 1.15
Фон секции: speed factor 0.3
Технически — каждой карточке присваивается data-атрибут со своим speed factor, общий скролл-обработчик применяет translateY индивидуально к каждой.
4. Пространства ресторана

Сетка: табы/переключатель сверху или сбоку (4 пункта — зал, терраса, бар, банкетный зал), под ним — область с крупным фото (16:9, минимум 1200×675px) и текстовым описанием поверх или сбоку.

Десктоп: табы горизонтально в ряд, ширина каждого таба — авто по контенту + padding 24px/16px. Mobile: табы — горизонтальный скролл (swipe) без переноса строк.

Отступы: между табами и фото-областью — 32px, внутренний padding текстового блока поверх фото (если оверлей) — 40px.

Параллакс:

Фоновое фото активной зоны: speed factor 0.4, с плавным cross-fade (300–400ms) при переключении таба
Карточка с названием зоны и описанием: speed factor 1.0, лёгкая тень box-shadow: 0 20px 40px rgba(0,0,0,0.15) для эффекта «приподнятости» над фоном
5. Меню (тизер)

Сетка: 3–4 колонки на desktop (по числу блюд, равные по ширине), 2 колонки на tablet, 1 колонка на mobile (карусель со свайпом рекомендуется для mobile, чтобы не растягивать секцию по высоте).

Изображения блюд: квадрат 1:1 или 4:5, минимум 600×600px, с мягкой тенью под объектом (filter: drop-shadow(...), если фото на прозрачном/однотонном фоне) для эффекта «парящей тарелки».

Отступы: gap между карточками блюд — 32px (desktop) / 16px (mobile), отступ от названия блюда до описания — 8px, до CTA-кнопки под секцией — 48px.

Параллакс:

Фон секции: speed factor 0.4
Фото блюд: speed factor 1.15, с индивидуальным небольшим сдвигом по Y относительно друг друга (разброс ±20px между соседними карточками), чтобы карточки не двигались строго синхронно — это усиливает ощущение «всплытия»
Текст под фото: 1.0
6. Как нас найти

Сетка: 2 колонки на desktop — карта 7/12, карточка контактов 5/12 (наложена внахлёст на карту с отступом -80px слева, если дизайн предполагает оверлап; либо чистое разделение колонок для более простой вёрстки). На tablet/mobile — карта сверху на всю ширину (высота 400px/320px), карточка контактов под ней.

Карта: встраивается через iframe (Google Maps/Yandex Maps embed) или интерактивную JS-библиотеку, aspect ratio контролируется через aspect-ratio: 16/9 на mobile и фиксированную высоту 560px на desktop.

Карточка контактов: padding 40px, фон — светлый (
#F7F3EA) с тонкой рамкой или тенью, список: адрес / часы работы / телефон / кнопка «Забронировать» (полная ширина карточки).

Параллакс:

Карта: speed factor 0.3 (максимально «заякорена»)
Карточка контактов: speed factor 1.0, с тенью 0 30px 60px rgba(0,0,0,0.2) для эффекта наложения поверх карты
7. Футер

Сетка: 3–4 колонки на desktop (логотип+копирайт / контакты / часы работы / соцсети), на mobile — стек в 1 колонку с центрированием.

Отступы: padding секции 64px сверху / 32px снизу (desktop), 48px/24px (mobile). Разделительная линия толщиной 1px, цвет rgba(255,255,255,0.15) (если футер тёмный) — перед копирайтом.

Параллакс: отсутствует — секция полностью статична, без transform на скролл (по замыслу — «остановка» после динамики выше).

Технические примечания по производительности
Все изображения — srcset + <picture> с WebP/AVIF, lazy-loading кроме hero и первого экрана видимости.
Параллакс — только через transform/opacity (не через top/margin), чтобы не триггерить layout reflow; обязательно will-change: transform на анимируемых слоях, но снимать это свойство после завершения анимации, чтобы не перегружать память.
На мобильных — обязательно проверить prefers-reduced-motion: reduce и полностью отключать параллакс-сдвиги для пользователей с этой настройкой (оставлять только fade-in).
